The only real content exclusive to v3.7.0 is `.engram` memory-sync artifacts and one near-twin (the scrollable backup list, whose code exists on main as `41acbe30`). **No user-facing product content is exclusive to v3.7.0.**

## What's new

### Facts-informed review (Go)

Review risk lenses now consume the Facts evidence index produced by Gentle Shell: an optional Facts subject digest section in lens prompts (`8d63b250`) and Facts-based risk signals derived from the declaration graph (`fa80c920`) — tests-only change detection, dependents reachability and symbol-surface deltas feed the review verdict inputs. Corrective hardening preserved coverage for nonlocal imports (`a3bab16d`), frozen JSON resource verification (`13f49df6`), and conservative handling of unindexed paths (`8c6749fb`), with directed production consumers (`ff38aab6`) and hermetic fixture isolation (`a7dd95bc`).

### Managed OpenCode plugin support (V1/V2)

Managed plugin assets for OpenCode (telemetry, model catalog, skill registry, review transport) shipped as V2 plugins targeting `@opencode/plugin` 2.0.4 (`43af401a`, #5115), alongside the V1 `@opencode-ai/plugin` path. Verified compatibility limits, as documented in `docs/opencode-compatibility.md`: native review admission requires a matching pair — the V1 path on a V1 runtime, or the exact managed V2 relay declaration (`gentle-ai.opencode-relay/v2-staged`) with a detected V2 runtime; admission was proven as transport on a real OpenCode 2.0.19 host with SDK 2.0.4 and network denied, and does not speak to reviewer quality. Community TUI plugins have unproven compatibility: installation and update refuse rather than silently omitting incompatible assets, and user-owned assets are preserved. Host caveat: OpenCode 2.0.19 skips later plugins' hooks after a throwing hook.

### Review hardening

Dangerous-sink detection (`0b459051`), risk assessment on agent escalation (`95ee74d0`), edge-detachment and disposition-line fixes (#2995), typed refusal on mounts that cannot represent private POSIX modes (`d5a85cd4`), and telemetry classification for subagent runs (#5050).

### Platform and workflow

OpenCode V2 plugin runtime (#5115), Conductor workspace orchestrator (`855ea658`), pi-mcp-adapter retired in favor of Pi built-in MCP (#5121), GPT-6.1 Codex presets (#5154), managed-assets manifest model (`0da1ab73`), JSONC-aware legacy marker cleanup (`96bed1cb`), RDD limited to Claude Code/Codex/OpenCode (`5ffb65fc`), scrollable TUI backup list (`41acbe30`), external community plugin retirement (#5200), and Windows path resolution for `gentle-ai.exe` (`72c492e8`).

## Breaking changes

1. **SDD and OpenSpec retirement** (`e219644b`, 870 files, +11,921/−118,573). SDD commands, profiles and the OpenSpec workflow integration are no longer offered. Independent RDD and Strict TDD remain; user-owned assets are preserved and OpenCode uninstall stays migration-safe (`3d01b376` restored non-SDD assets the retirement had dropped). Motivating change for the major version.
2. **Go module path moved to `/v4`** (`a9f1390da`; 628 files). Consumers must import `github.com/gentleman-programming/gentle-ai/v4/...`. Release linkage, installers and guidance were aligned with the new module major (`9696205e`, `16e11590`, `8d6f4560`, `c2dc7129`).

## Windows

Nine test surfaces corrected to preserve platform-specific assertions in release checks (PR #5076, `26d461590` → `61692e5ff`; +103/−26, tests only), followed by Windows Full Suite greening (#5174) and npm stub follow-ups (#5187). Cross-compilation was never substituted for runtime proof: the Windows corrections restore meaningful assertions, and the v4 gating requires exact-main Windows Full Suite success before any release.

## Upgrade

- Go consumers: `go install github.com/gentleman-programming/gentle-ai/v4/cmd/gentle-ai@v4.0.0` (path changes from `/v3` to `/v4`).
- Homebrew: published to `Gentleman-Programming/homebrew-tap` on release day (pending — publication is deferred and gated on exact-main CI plus Windows Full Suite).
- SDD users: SDD commands and profiles are gone; migrate workflows to ODD/RDD before upgrading. OpenCode users: read `docs/opencode-compatibility.md` for the managed-plugin contract before upgrading plugins.
